# Research

The studies behind StateSync, kept apart from the product. Nothing here is imported by the app. The
experiments ran against the system **as it was then**, which had switches for every experimental variant;
those switches were removed in the clean-up. To re-run one, check out its tag first:

| Tag | What it is |
|---|---|
| `paper-b-submission` | the repository as Paper B was submitted (ICDEC 2026) |
| `pre-cleanup-2026-10-26` | the last version with every experimental switch (Paper A's and Paper B's runs) |

```bash
git worktree add ../statesync-research pre-cleanup-2026-10-26   # a separate checkout; the app here is untouched
```

The scripts there are under `scripts/`, the results under `docs/eval/`, the protocols under `docs/research/`.
In this branch the same files live in the folders below.

## paper_a/: warning signals for wrong text-to-SQL answers

*Testing Text-to-SQL Warning Signals: A Pre-registered Study of Data Checks, Judges and Self-Consistency*
(IEEE format, for MoSICom 2026).

| Folder | Holds |
|---|---|
| `paper/ieee/` | the paper's LaTeX source and PDF |
| `paper/` | earlier drafts, the audit and pre-submission notes, the risk-coverage figure |
| `protocols/evidence_tiers_study.md` | the pre-registered protocol (versions and change log) |
| `scripts/` | `eval_bird.py` (runs the pipeline on BIRD Mini-Dev), `annotate_bird.py` (blind annotation), `analyze_bird.py` (the confirmatory analysis), `plot_bird.py`, the exploratory analyses, `bird_db.sh` (the BIRD databases) |
| `results/` | every run's answers, scores and reports (`bird_*`) |
| `tests/` | the tests of those scripts |

Main result: on 393 held-out questions, data checks apply to 4% of answers and catch no more errors than an
LLM judge at the same rate; "the agent had to retry" is the best free warning (79% precision).

## paper_b/: a typed decision model on an assistant's decisions

*Evaluating a Typed Decision Model on the Decisions of a Database-and-Documents AI Assistant* (Springer LNNS,
ICDEC 2026, submitted).

| Folder | Holds |
|---|---|
| `paper/latex/` | the paper's LaTeX source; `numbers.tex` is generated by `scripts/paperb_numbers.py` from the result files, so every number in the paper traces to a file (the script's paths are those of the `paper-b-submission` tag: run it there) |
| `paper/` | the literature review, the audit, the project guide written for the review, the Decision Lab demo page |
| `protocols/` | the pre-registrations: `paperb_reruns_prereg.md` (R1–R4, the reruns the paper reports), `jev_pages_confirmatory.md`, `detect_then_fallback_study.md` |
| `scripts/` | the experiments: SQL checking (`paperb_*`), routing (`build_routing_set*.py`, `eval_routing.py`, `fit_jev_thresholds.py`), page finding (`build_page_set.py`, `eval_jev_pages.py`), answerability (`eval_jev_answerable*.py`), FinanceBench end to end (`eval_financebench.py`) and its data fetch (`fetch_external_eval.sh`) |
| `results/` | every run's outputs (`paperb_*`, `routing_*`, `partd_*`, `financebench_*`, `jev_*`, `page_*`, `turns_*`) |
| `stack/` | the experiment stack: settings for each arm (`flags_partd_*.toml`), the scripts that ran it, and the old separate demo copy |
| `reranker/` | the bge cross-encoder service the experiments compared against |

Main results: one four-way Jev choice question routes as well as an LLM router (88.3% vs 84.4%, n.s.) while
two yes/no questions do worse (75.6%); a coverage line of what the database holds lifts both routers; Jev's
passage order puts the right filing page first 53.3% of the time against 43.7% for a GPU cross-encoder; Jev
judges SQL about as well as existing methods but not better.

## verifier/

An earlier study of a set-up-time verifier (Laya): mutated SQL did not transfer to real errors, while real
candidates helped their own generator. Scripts, runs and results.

## archive/

Everything from the project's earlier phases that is no longer part of the product: the phase plans and logs,
cycle and audit records, the strategy and build documents, the August–October reports and benchmark outputs
(`docs/`, `results/`), the old evaluator service and live-data simulator, implementation specs
(`specs/implementation_specs/`), the benchmark and fixture scripts (`scripts/`) and their tests (`tests/`),
including the earlier live security suite (`scripts/verify_security.sh`, 43 of 44 checks on the old sample
data). `docs/AUDIT_2026-10-26.md` is the audit that started the clean-up.
